## 0. How to use this document

1. قبل از پیاده‌سازی هر صفحه عملیاتی (لیست، فرم، سند، کارتابل، گزارش)، بخش مرتبط را بخوان.
2. در صورت تعارض بین سلیقه لحظه‌ای و این سند، **این سند برنده است**.
3. مرجع بصری زنده: `http://localhost:3000/dashboard/ui-guide` (و معادل production).
4. UI-09 Charts از نظر کیفیت نهایی deferred است؛ قوانین عمومی گزارش در بخش ۹ معتبر است ولی جزئیات بصری نمودار تا بازبینی بعدی قفل سخت نیست.
5. هر تغییر در این سند فقط با Architecture Amendment و به‌روزرسانی هم‌زمان UI Guide مجاز است.

## 1. Cross-cutting (اعمال روی همه صفحات)

### 1.1 زبان، جهت، عدد

| موضوع | قانون |
|------|--------|
| زبان UI | فارسی |
| جهت | RTL (`dir="rtl"`) |
| اعداد نمایشی | ارقام فارسی در برچسب‌ها در صورت سیاست محصول؛ **مقادیر مالی و کدهای سیستمی با `dir="ltr"`** |
| مبلغ مالی | جداکننده هزارگان؛ اعشار درست؛ هرگز رشته خام بدون فرمت |
| Package manager | فقط **pnpm** |

### 1.2 بدون Reload اجباری

- ذخیره، پیش‌نویس، فیلتر، صفحه‌بندی، تغییر وضعیت پس از Workflow: **بدون full page reload**.
- DOM ساختاری صفحه بعد از submit نباید از بین برود (اصل DOM پایدار از UI-04).

### 1.3 رنگ و توکن

- رنگ فقط از Design Token / پالت مستأجر (UI-00) — نه هگز پراکنده در کامپوننت.
- وضعیت (Status) **فقط با رنگ منتقل نمی‌شود**؛ همیشه متن (و در صورت نیاز آیکون) همراه رنگ است (UI-11).

### 1.4 آیکون (سیاست B+D — قفل)

| سطح | مجموعه |
|-----|--------|
| پایه عمومی | Lucide Outline |
| Sidebar L1 / Header / کارت ماژول | Chip / Brand |
| Empty / Hero / Onboarding | Phosphor Duotone فقط |
| ممنوع | Tabler |

### 1.5 دسترسی پایه (UI-11)

- همه کنترل‌های تعاملی با صفحه‌کلید قابل‌دسترسی.
- `focus-visible` حلقه واضح؛ `outline: none` بدون جایگزین ممنوع.
- دکمه‌های فقط‌آیکون: `aria-label` اجباری.
- `prefers-reduced-motion: reduce` → انیمیشن تزئینی خاموش یا آنی.
- پیام مهم موفقیت/خطا: `aria-live="polite"` در صورت عدم جابه‌جایی فوکوس.
- ترتیب Tab منطقی و منطبق بر DOM RTL.

## 2. Branding & Tenant Theming (UI-00)

- توکن رنگ مستأجر + اسلات لوگو / شعار / Favicon.
- پشتیبانی Dark / Light از همان توکن‌ها.
- هیچ ماژولی پالت مستقل invent نمی‌کند.

## 3. Foundations (UI-01)

- تایپوگرافی، فاصله، شعاع، Elevation + hover، الگو، Density از Design System.
- Density قابل‌تعویض در صفحات عملیاتی پرتراکم (انبار، خطوط سند).

---

## 4. Layout & Structure (UI-02) — حیاتی

### 4.1 Shell و چیدمان

- App Shell ثابت؛ محتوای اصلی با max-width و فاصله استاندارد.
- Sticky فقط جایی که ارزش دارد (toolbar جدول، فیلتر گزارش) — نه چسباندن بی‌مورد همه چیز.

### 4.2 Overlay و فرم کثیف (Dirty) — Non-Negotiable

| حالت فرم | کلیک بیرون / Escape | بستن مجاز با |
|----------|---------------------|--------------|
| تمیز (بدون تغییر) | مجاز | بیرون، Escape، انصراف، ثبت |
| کثیف (dirty) | **مسدود** | فقط **ثبت** یا **انصراف** صریح |

- انصراف: بدون confirm اضافی مگر تصمیم معماری خلاف آن.
- پس از ثبت موفق: بستن overlay + بازخورد در صفحه؛ **بدون reload**.

این قانون برای Modal، Drawer و هر لایه مسدودکننده یکسان است (UI-02 + UI-07 + UI-08 Approval).

## 6. Forms & Data Entry (UI-04)

| قانون | جزئیات |
|------|--------|
| برچسب | Label همیشه؛ فیلد اجباری با `*` |
| خطا | **زیر همان فیلد**؛ نه فقط Toast |
| چیدمان | ۱–۲ ستون؛ از شلوغی ۳+ ستون در فرم عملیاتی پرهیز |
| ثبت | بدون reload؛ پیام موفقیت در context |
| تب + پیش‌نویس | پشتیبانی از ذخیره موقت در اسناد چندبخشی |
| DOM | بعد از submit ساختار ثابت بماند |

## 7. Data Display & Tables (UI-05)

### 7.1 جدول

- ستون‌های زیاد: کاربر می‌تواند ستون‌های قابل‌نمایش را تا سقف معقول عرض صفحه انتخاب کند؛ اولویت با فیلدهای مهم؛ بقیه از مسیر جزئیات / popover / پنل.
- در نمای جزئیات کامل: ترتیب فیلدها مطابق اولویت دامنه/دیتابیس.
- رکورد زیاد: **انتخاب page-size** اجباری.
- Stripe / تفکیک سطر ملایم؛ hover از پالت — شلوغ و جیغ نباشد.
- اگر داده توسط کاربر دیگر عوض شده: نشان **stale / به‌روزرسانی موجود** و امکان refresh آگاهانه.

### 7.2 Empty states

| موقعیت | پیام |
|--------|------|
| بارگذاری اولیه بدون داده | Empty آرام («موردی ثبت نشده») |
| جستجو/فیلتر بدون نتیجه | **متفاوت** («نتیجه‌ای برای این جستجو نیست») — هرگز شبیه لودینگ خالی |

### 7.3 مالی در سلول

- جداکننده هزارگان؛ اعشار صحیح؛ `dir="ltr"` برای مقدار.

### 7.4 مدل‌های جایگزین

- علاوه بر جدول: List و Card برای موجودیت‌های مناسب (نه فقط انبار) طبق Guide.

## 8. Feedback, Status & Loading (UI-06)

| نوع | کاربرد |
|-----|--------|
| خطای فیلد | زیر فیلد (نه جایگزین Toast) |
| Toast | بازخورد کوتاه سیستمی؛ نه اعتبارسنجی فیلد |
| Alert | پیام پایدار در صفحه |
| Status Chip | وضعیت دامنه با متن+رنگ |
| Overlay مسدود | عملیات غیرقابل‌قطع |
| Loading | اسکلت / پیشرفت؛ همدلانه نه ترسناک |

- مدل‌های لودینگ برای صفحه کامل و بخش‌های در حال عملیات؛ انیمیشن آرام؛ با reduced-motion سازگار.

---

## 9. Overlays (UI-07)

- Modal / Drawer / Popover / Tooltip با نقش مشخص.
- **یک** لایه مسدود فعال در یک لحظه.
- Escape + backdrop مطابق قانون dirty (بخش 4.2).
- Tooltip: اطلاعات کمکی؛ نه اقدام حیاتی فقط داخل Tooltip.

---

## 10. Workflow & Process (UI-08)

| الگو | قانون |
|------|--------|
| تغییر وضعیت سند | **فقط از مسیر Workflow** — نه دکمه آزاد UI |
| Stepper | وضعیت فعلی روشن؛ آینده غیرفعال؛ گذشته قابل‌مشاهده |
| Approval | Modal/Drawer با dirty-lock UI-02 |
| Timeline | هر رخداد: کاربر، نقش، واحد، وضعیت قبل/بعد |
| Kanban | فقط transition مجاز؛ میانبر + drag در صورت پیاده‌سازی پایدار |
| Worklist | اسناد منتظر اقدام با واحد و نقش درخواست‌کننده |
| بعد از تصمیم | بدون reload صفحه |

## 11. Charts & Reporting (UI-09) — قوانین عمومی

> کیفیت بصری پیشرفته نمودار deferred است؛ تا بازبینی، حداقل‌های زیر لازم‌الاجرا است.

- عدد مالی خوانا (جداکننده، LTR).
- KPI محدود و معنادار (نه ۱۰ کارت بی‌هدف).
- فیلتر گزارش بدون reload؛ ترجیحاً preset + بازه از/تا.
- Empty نمودار ≠ خطا.
- رنگ از توکن.
- انتخاب نوع نمودار بر اساس نوع سؤال داده (روند → Line/Area؛ سهم → Donut≤۵؛ دو مقیاس → Combo؛ رتبه → Bar افقی/جدول؛ چگالی زمانی → Heatmap).

## 12. Real-world Composition (UI-10)

### 12.1 صفحه لیست عملیاتی

جریان ثابت: **فیلتر/جستجو → جدول → پنل جزئیات** (کنار یا پایین).

- Toolbar جدول فشرده: جستجو + فیلتر + Density + اقدام اصلی (مثلاً سند جدید).
- انتخاب ردیف → جزئیات بدون اجبار route جدید.
- Empty جستجو ≠ Empty اولیه.

### 12.2 فرم سند (هدر + خطوط + فوتر)

| ناحیه | محتوا |
|-------|--------|
| هدر | عنوان، وضعیت، فیلدهای سربرگ |
| بدنه | خطوط اقلام قابل‌ویرایش |
| فوتر | **جمع مالی زنده** + ذخیره پیش‌نویس + ارسال برای تأیید |

- افزودن/حذف ردیف درجا.
- ذخیره بدون reload.

### 12.3 فضای صفحه

- بالای fold: عنوان/وضعیت، اقدام اصلی، فیلتر پرتکرار.
- یک اسکرول عمودی غالب؛ از اسکرول تو‌در‌تو بی‌مورد پرهیز.
- بدون کارت تزئینی خالی بین فیلتر و جدول.

## 13. Accessibility checklist before «ready» (UI-11)

- [ ] ترتیب Tab منطقی؛ focus trap در Modal درست
- [ ] همه کنترل‌های آیکونی `aria-label` دارند
- [ ] خطای فرم به فیلد وصل است
- [ ] انیمیشن‌ها با reduced-motion بی‌ضررند
- [ ] بازخورد مهم در live region یا فوکوس مدیریت‌شده
- [ ] کنتراست متن/Badge در تم روشن و تیره قابل‌قبول است

## 14. Global Do / Don’t

### Do

- ارجاع به این سند + UI Guide زنده قبل از invent الگو
- Dirty-lock روی overlayهای دارای فرم
- مبلغ و کد با فرمت و LTR
- وضعیت با متن + رنگ
- Workflow برای تغییر وضعیت سند
- Empty متفاوت برای جستجوی خالی
- pnpm، RTL، توکن رنگ، آیکون B+D

### Don’t

- Reload بعد از ثبت/فیلتر
- بستن Modal dirty با کلیک بیرون
- Toast به‌جای خطای فیلد
- تغییر وضعیت سند با دکمه آزاد خارج از Workflow
- outline حذف‌شده بدون focus-visible
- آیکون بدون نام دسترس‌پذیر
- رنگ خارج از Design Token
- صفحه لیست بدون تفکیک Empty جستجو / Empty اولیه
- فرم سند بدون فوتر جمع
